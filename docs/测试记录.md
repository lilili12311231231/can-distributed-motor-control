# 测试记录

> **说明**：本项目完成时没有留存实物照片与演示录屏，硬件也已拆散，因此本文档以**配置参数**和**已验证行为**为主，实测数据单列在第四节。
> 凡标注「推导」的参数都可由代码/时钟直接算出；凡标注「待补」的都不做推测性结论。
> 第一节与第二节的结论，可以用 `tools/protocol_selfcheck.py` 直接从源码抓参数复核，不需要接硬件。

---

## 一、通信参数（可从代码推导）

| 项目 | 值 | 推导依据 |
|---|---|---|
| CAN 波特率 | 500 Kbps | 主站 PCLK1 42 MHz ÷ Prescaler 7 = 6 MHz；从站 PCLK1 36 MHz ÷ Prescaler 6 = 6 MHz；(1+7+4) TQ = 2 μs/bit |
| 采样点 | 66.7% | (1 + BS1 7) / 12 |
| 帧格式 | 标准帧、数据帧、DLC = 4 | `IDE = CAN_ID_STD`、`RTR = CAN_RTR_DATA` |
| 命令 ID / 反馈 ID | 0x181 / 0x201 | 代码中 `StdId` 硬编码 |
| 从站滤波器 | 仅收 0x181 | `FilterIdHigh = 0x181<<5`，掩码高 16 位全比较 |
| 电机串口 | 38400、8N1、地址 0xE0、和校验 | `MX_USART1_UART_Init` + `Servo_SendCommand` |
| 看门狗 | 约 2.0 s | LSI 40 kHz ÷ 64 = 625 Hz；(1249+1)/625 = 2.0 s |
| 主站切换周期 | 3 s | `HAL_GetTick() - last_switch > 3000` |
| 从站回传周期 | 50 ms | 主循环 `HAL_Delay(50)` |
| 定位等待 | 500 ms | 定位分支内 `HAL_Delay(500)` |

## 二、坐标换算（可验证的算术）

| 项目 | 值 | 校验 |
|---|---|---|
| 编码器分辨率 | 65536 计数/圈（16 位） | 90° = 65536/4 = 16384 ✅ |
| 电机细分步数 | 3200 步/圈（Mstep = 16） | 驱动参数 |
| 1 步对应的计数 | 65536 / 3200 = 20.48 | ✅ |
| 代码换算系数 | `× 25 / 512` | 3200/65536 = 0.048828125 = 25/512 ✅ |
| 90° 对应步数 | 16384 × 25 / 512 = **800** 步 | ✅ |
| 180° 对应步数 | 32768 × 25 / 512 = **1600** 步 | ✅ |

> 换算系数用整数分式而不是浮点，是为了让计算在 int32 里精确可复现，避免 `0.0488` 这类近似值在多次定位后累积偏差。

## 三、已验证行为（据开发过程记录）

| 项 | 验证方式 | 结果 |
|---|---|---|
| 上电初始化链路 | 依次发 0x82 / 0x85 / 0xF3，各步有应答 | 通过 |
| CAN 收发 | 主站发 0x181，从站进中断并置标志 | 通过 |
| 手动回零 | 按下 PA0 后记录 `home_full`，后续定位以它为基准 | 通过 |
| 90° ↔ 180° 往返定位 | 主站每 3 s 切换目标，电机往复到位 | 通过 |
| 位置回传 | 从站 50 ms 周期发 0x201，主站可读 | 通过 |
| 看门狗 | 主循环持续喂狗，系统不误复位 | 通过 |

> 上述"通过"指功能跑通，**不含精度指标**——精度数据见下一节。

## 四、待补实测（尚未采集）

项目收尾时硬件已拆散，这一节的项目**现在补不了**。列出来是为了两件事：一是不把"没测"说成"测了"；二是将来重新搭起来（或换一套硬件）时能直接照着做，不用重新设计验证方案。

以下项目当前**没有数据**，不做推测：

| 待测项 | 建议方法 | 期望输出 |
|---|---|---|
| 单次定位误差 | 串口打印 `target_pos` 与定位后 `Servo_ReadEncoder() - home_full` | 误差（计数 / 度），例如 `±N 计数` |
| 往返重复精度 | 90°↔180° 连续往返 20 次，记录每次到位值 | 最大值/最小值/极差 |
| 到位耗时 | 记录发 0xFD 到编码器稳定所需 tick | 与 `HAL_Delay(500)` 的余量对比 |
| CAN 波形与时序 | 逻辑分析仪抓 CAN_H/CAN_L 或 CAN 分析仪 | 帧间隔、ACK 位、错误帧计数 |
| 总线容错 | 运行中拔掉 CAN_L，观察是否进入 Bus-Off 及能否恢复 | 验证 `AutoBusOff = DISABLE` 的实际影响 |
| 连续运行 | 通电往复 30 min 以上 | 有无丢帧、位置漂移、看门狗误触发 |
| 多从节点 | 加第二块 F103（NodeID=2，ID 改 0x182/0x202） | 两节点独立定位互不干扰 |

**补测步骤（定位误差，最简单的一条）**：
1. 从站 `main.c` 定位分支里，在 `Servo_SetPosition()` 之后加 `HAL_Delay(600)`，再读一次编码器；
2. 串口打印 `delta_enc` 与目标值；
3. 反复 20 次，记录差值的最大/最小值 —— 这就是重复精度。

## 五、无硬件条件下的替代验证

实测做不了，但「参数是否自洽」这类错误不需要硬件就能查。`tools/protocol_selfcheck.py` 从源码里抓时钟、Prescaler、帧构造规则，重算一遍并断言，共 69 项：

```bash
python tools/protocol_selfcheck.py     # 退出码 0 = 全部通过
```

它能挡掉的问题：两节点波特率不一致、校验和算错、0xFD 帧长度撑爆缓冲区、方向位与幅值没拆开、换算系数写错。**这些都属于"代码能编译、烧进去却不动作"的类型，靠看代码很难发现。**

挡不掉的问题：真实定位精度、到位耗时、总线抗干扰能力 —— 这些只能靠第四节列的方法实测。
